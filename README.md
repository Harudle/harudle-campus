# 하루들 우테코 캠퍼스

하루들 캐릭터로 우아한테크코스 판교 캠퍼스 11~14층을 걸어 다니는 3D 메타버스입니다.
크루를 누르면 그 사람의 하루들 공개 피드(네 컷 만화)가 열립니다.

## 기능

- 11~14층 종이 디오라마 (three.js 0.170, 툰 셰이딩 + 먹선 윤곽, 덕후감 3D 서고 방식)
- 입체 하루들 캐릭터와 강아지
- 이동 WASD·방향키·클릭 / 달리기 Shift / 점프 Space / 대화·엘리베이터 F
- 스킬 1 네 컷 그리기 · 2 인사 · 3 하트
- 같이 접속한 크루의 위치·말풍선·스킬 실시간 공유 (WebSocket)
- 하루들 공개 피드 실시간 중계 (`/api/feed`, 4분 캐시)
- 판교 캠퍼스 기준 실제 시간에 따른 해와 달, 하늘과 빛, 날씨 예보에 따른 창밖 비와 눈
- 캠퍼스 주변 건물과 도로, 하천을 참고한 창밖 풍경
- 음성 연결을 켠 크루끼리 가까운 거리에서 대화하고, 회의실에서는 화면을 공유
- **14층 하루들 월드**: 14층은 [하루들 월드](https://github.com/Harudle/harudle-world)를 옮긴 층이라 엘리베이터 홀 말고는 월드 공간만 있습니다. 북쪽 전체가 메인 전시실(보라 카펫 끝 "가장 사랑받은 만화", 벽과 앞줄 이젤 액자에 인기 네컷만화, 작가 체험 부스, 다 같이 그리는 네컷 이젤과 지난 그림 스케치북, 큰 하루들 휴대폰, 꽃게 게임 만화가 걸린 액자 앞에서 점프하면 그림 속으로 뛰어들어 게임 시작), 서쪽 위가 작가 전시실 여덟 곳(작가 만화, 그 작가 만화를 모두 넘겨 보는 앨범북, 응원 방명록), 서쪽 아래가 퀴즈 아케이드(파스텔 바둑판 바닥과 전구 간판, 인형 뽑기·주크박스·팝콘 수레 같은 소품, 가운데 입구 홀 양옆에 노래 맞추기 방·드라마·영화 맞추기 방, 방마다 뒷벽과 옆 벽에 문제 액자), 동쪽이 릴레이 만화 소설관(나무 바닥 긴 복도, 보라 카펫 끝 이젤에 최신 화, 왼쪽 벽 필름에 지난 화, 오른쪽 벽 두루마리)입니다. 엘리베이터 홀 남쪽 문 앞 광장에는 오늘의 특종 가판대가 홀 쪽을 보고 서 있어, 남쪽 문을 나서면 앞면이 바로 보입니다. 액자·부스·이젤·가판대를 누르거나 앞에서 F를 누르면 월드의 그 창이 그대로 열립니다. 이젤은 월드와 같은 실시간 이젤이라 여러 사람이 같은 그림에 그리고, 14층 이젤 판에는 15초마다 지금 그림(`/easel/art`)이 보입니다. 응원글·퀴즈·이어 그리기·이젤 그림은 캠퍼스 서버에 따로 저장되고, world.harudle.com과는 섞이지 않습니다

## 구조

Vite + React + TypeScript + React Three Fiber. 캐릭터는 [하루들 월드](https://github.com/Harudle/harudle-world)의 컴포넌트를 그대로 씁니다.

```

├─ harudle/            하루들 월드에서 가져온 캐릭터 (Avatar, Characters, toon, avatar 데이터)
```

### 14층 하루들 월드

- 14층 배치는 `src/engine/world.ts`의 `f === 14`에 있습니다. 전시관과 소설관은 벽 없는 구역이고, 액자는 세워 두는 `showframe`과 벽에 거는 `showwall`(흰 전시 벽, `style: "film"`이면 필름 띠)로 `src`(work·a0~a7(작가 방)·cheer·crab·relay·song·drama)와 `slot`(몇 번째)을 정합니다. 위에서 보는 카메라가 남쪽에 있어서 액자는 되도록 남쪽을 보게 둡니다. 가판대는 `scoopstand`입니다. `showwall`·`showframe`·`relayscroll`에 `face: "e"|"w"`를 주면 옆 벽에 세워 안쪽을 봅니다. 방 벽색은 `R(..., { wall })`, 바닥 무늬는 구역의 `checker`(바둑판)·`planks`(나무판)입니다. 액자 그림은 14층에 처음 올 때와 10분마다, 무언가 올리거나 건 뒤에 다시 받습니다.
- 액자를 누르면 `/world/campus.html#artwork=…`처럼 그 창만 캠퍼스 위에 띄웁니다(바탕이 비어 14층이 비쳐 보임). 월드의 Tailwind 스타일이 캠퍼스와 섞이지 않게 같은 주소의 페이지로 따로 엽니다. 하루들 월드 전체 화면(`/world/`)도 함께 빌드되지만 캠퍼스에서는 쓰지 않습니다. 월드의 Tailwind 스타일과 키 조작이 캠퍼스와 섞이지 않게 하려는 것입니다. 같은 주소라 저장 공간을 함께 쓰므로, 처음 들어가면 캠퍼스 캐릭터와 이름을 월드에 넘겨줍니다.
- 월드 실시간 접속은 `/world/ws`, API는 월드와 같은 경로(`/cheers`, `/quizzes`, `/relay`, `/crab-game`, `/easel`, `/api/v1/feeds` 등)를 `app.js`가 받습니다. DB는 `.data/world/`(`WORLD_DATA_DIR`)에 두며 git에 올라가지 않고 배포(`git reset`)에도 지워지지 않습니다. 허용 주소는 `WORLD_ORIGINS`(기본 campus.harudle.com과 localhost)입니다.
- **서버 Node 22.13 이상이 필요합니다** (`node:sqlite`). 그보다 낮으면 캠퍼스는 그대로 돌고, 14층 월드만 연결 안 됨으로 보입니다. 워커 로그에 `[world] 14층 하루들 월드를 켜지 못했어요`가 찍힙니다.
- 월드의 큰 휴대폰 화면(하루들 바로 쓰기)은 www.harudle.com을 띄우는데, 하루들이 world.harudle.com에서만 띄우도록 허용해 두어서 캠퍼스에서는 비어 보입니다. 아래 `하루들 열기` 버튼은 동작합니다. 하루들 쪽 `frame-ancestors`에 campus.harudle.com을 더하면 풀립니다.
- 월드가 바뀌면 하루들 월드 저장소의 `src/`, `server/`(`index.ts`·`metamoa.ts`·`staticSite.ts` 제외)를 `world/`에 다시 복사하고, 아래 캠퍼스 수정만 다시 붙인 뒤 `npm run build` 하면 됩니다.
  - `world/src/data/presence.ts`: 실시간 주소 `/ws` → `/world/ws`
  - `world/src/index.css`: `@import 'tailwindcss' source('..');`
  - `world/index.html`: 스크립트 경로 `/world/src/main.tsx`, 제목


하루들 월드 캐릭터가 바뀌면 `src/harudle/`의 파일을 다시 복사하고, `Avatar.tsx`의 pose 부분만 다시 붙이면 됩니다.

### 캠퍼스 밖 풍경

[금토로80번길 40 주변 네이버 지도](https://map.naver.com/p/search/%EA%B2%BD%EA%B8%B0%EB%8F%84%20%EC%84%B1%EB%82%A8%EC%8B%9C%20%EC%88%98%EC%A0%95%EA%B5%AC%20%EA%B8%88%ED%86%A0%EB%A1%9C80%EB%B2%88%EA%B8%B8%2040)의 위성사진과 2026년 6월, 8월 거리뷰를 참고해 건물과 도로, 하천을 새로 그렸습니다. 실제 사진은 사용하지 않습니다. 실내 크기에 맞추어 위치와 높이를 조정한 대략적인 모습으로, 실제 창문에서 보이는 풍경과 정확히 같지는 않습니다. 창밖 건물과 지면은 판교의 시간과 구름량에 따라 밝기가 바뀝니다. 캠퍼스 실내는 밤에도 천장 조명이 켜진 것처럼 밝게 유지합니다. 도로의 차량은 실제 교통 정보가 아닌 풍경 연출입니다.

## 로컬 실행

```bash
npm install
npm run serve   # 다른 창에서: 피드·실시간·14층 월드 서버 (http://localhost:8080)
npm run dev     # 화면 개발 (Vite)
npm run build   # tsc → dist/ → dist-artifact/(아티팩트용 한 파일) → 지문
npm run check   # 배포 전 검사
```

**커밋 전에 꼭 `npm run build`.** 소스와 dist가 다르면 서버가 배포하지 않습니다.

## 음성과 화면 공유

- 음성 연결 버튼을 누르면 마이크도 켜진 채로 연결됩니다(처음엔 브라우저가 마이크 권한을 묻습니다). 마이크 버튼으로 끌 수 있고, 권한이 없으면 듣기만 연결됩니다.
- 열린 공간에서는 같은 층의 12칸 이내에 있는 크루끼리 대화합니다. 회의실이나 강의실처럼 구분된 방에서는 같은 방 사람끼리 대화합니다.
- 회의실에서 화면 공유를 시작하면 같은 방의 사용자에게 화면 패널이 표시됩니다. 방을 나가면 화면 공유가 끝납니다.
- 브라우저가 지원하고 사용자가 소리 공유를 선택한 경우 화면에서 나오는 소리도 함께 전달할 수 있습니다.
- 회의 선택을 켜면 회의실에서 공개 또는 비공개 회의를 만들 수 있습니다. 비공개 회의는 비밀번호가 있어야 들어갈 수 있습니다. 운영용 회의 목록은 서버가 다시 켜져도 유지되며 24시간 뒤 만료됩니다.
- 같은 회의의 근처 채팅은 다른 회의에 전달되지 않습니다. 전체 채팅은 모든 사용자에게 보입니다. 아직 사용자 인증이 없고 위치도 브라우저에서 보내므로 민감한 대화에 사용하지 않습니다.
- 음성 연결을 유지하는 동안 현재 제공자의 사용량이 쌓입니다. 마이크를 꺼도 연결 시간은 누적되므로, 연결을 마치면 음성 나가기를 누릅니다.

## 채팅 명령어

채팅창에 `/`를 입력하면 명령어 목록이 뜹니다. ↑↓로 고르고 Tab으로 채웁니다. 명령어는 채팅으로 보내지 않습니다. 없는 명령어도 채팅으로 보내지 않고 안내만 합니다. `/`로 시작하는 글을 그대로 보내려면 `//`로 시작합니다. 명령어 목록은 `src/chat/commands.ts`에 있습니다.

- 말하기: `/전체 내용` `/근처 내용` `/귓 이름 내용` `/me 행동` `/주사위 [최대 수]` `/뽑기 A B C`
- 동작: `/춤 [이름·번호·목록]` `/인사` `/하트` `/그리기` `/폭죽` `/커피` `/노트북` `/책` `/총`
- 이동과 크루: `/층 13` `/찾기 [이름]` `/따라가기 이름` `/멈춤`
- 음성: `/음성` `/마이크`
- 대결: `/대결 이름 [종목]` `/수락` `/거절` `/관전 [이름]` `/종료` `/기권` `/전적 [이름]`
- 창: `/설정 [음성·조작법]` `/조작법` `/프로필` `/외형` `/인벤토리` `/상점` `/안내` `/도움`

주사위와 뽑기 결과는 서버가 정해서 보내므로 브라우저에서 바꿀 수 없습니다. 영어 이름(`/dance`, `/floor`, `/roll`)도 사용할 수 있습니다.

## 1:1 대결

`/대결 이름 [종목]`으로 크루에게 1:1 대결을 신청합니다(종목을 빼면 고르는 창). 상대 화면에 초대장이 뜨고 버튼, Y · N, 또는 채팅 `/수락` · `/거절`로 답합니다. 초대장은 답하거나 30초가 지날 때까지 남아 있습니다. 같은 상대에게는 5초에 한 번 신청할 수 있습니다. 수락하면 둘 다 건물 위 하늘에 떠 있는 대결장(21~24층)으로 옮겨 가 3 · 2 · 1 뒤에 겨루고, 결과를 본 뒤 원래 있던 자리로 돌아옵니다. `/관전 이름`으로 진행 중인 경기를 보고, `/기권`으로 그만두며, `/전적`으로 승 · 패 · 무와 점프맵 기록을 봅니다. 설정창에서 "대결 신청 받기"를 끌 수 있습니다.

- 종목: 점프맵(21층, 코스 넷 중 서버가 고른다) · 사격 대결(22층) · 과녁 사격(23층) · 복싱(24층). 네 종목 모두 열려 있습니다.
- 대결장에서는 같은 경기의 선수와 관전자만 서로 보이고, 근처 채팅과 음성도 그 안에서만 오갑니다(화면 공유는 꺼짐). 크루 목록에는 "⚔️ 대결 중" · "👀 관전 중"으로 보입니다.
- 서버(`server/duel/`)가 신청 · 경기 단계 · 판정을 정하고, 끊긴 선수는 20초 기다렸다 기권패로 합니다. 전적은 임시 폴더의 `harudle-duels.json`에 남습니다.
- 설계와 종목을 더하는 방법(배치 · 서버 규칙 · 브라우저 `ctx`)은 [docs/duel.md](docs/duel.md)에 있습니다.

## 스타트랙 유튜브 함께 보기

- 13층 스타트랙 왼쪽 위의 `영상 설정`을 누르거나 큰 화면 가까이에서 가운데 상호작용 버튼 또는 F를 눌러 유튜브 영상 링크를 등록합니다. 링크를 넣은 뒤 일반 영상인지 라이브 방송인지 선택합니다. `/live/` 주소는 라이브로 미리 선택됩니다. 이미 등록한 영상의 종류가 다르면 설정에서 현재 영상의 종류를 바꿀 수 있습니다.
- 유튜브 재생기는 16:9 비율의 스타트랙 3D 큰 화면에만 나타납니다. 화면의 기존 가로 크기를 유지하고 세로와 천장을 높였습니다. 카메라의 시야각과 방향은 기존 캠퍼스 조작을 그대로 따르며, 화면 일부가 잘려도 별도 창은 뜨지 않습니다. 스타트랙을 벗어나면 영상이 보이지 않습니다.
- 영상은 각자의 기기에서 유튜브가 재생하고 캠퍼스 서버는 영상 주소와 재생 상태만 공유합니다. 일반 영상에 늦게 들어온 크루는 현재 재생 위치에 맞춥니다. 라이브는 각 기기에서 현재 방송을 재생하며 광고와 연결 속도에 따라 시점이 다를 수 있습니다.
- 재생 중 다른 영상을 등록하면 모두의 화면이 새 영상으로 바뀌어 계속 재생합니다. 일시정지 중이었다면 새 영상도 일시정지 상태입니다. 일반 영상은 재생바나 설정의 시간 이동을 사용하면 그 위치를 다른 크루와 공유합니다. 라이브 재생바 이동은 내 화면에만 적용하며 유튜브의 Live 버튼을 누르면 현재 방송으로 돌아갑니다.
- 소리는 화면과의 거리에 따라 작아집니다. 12층을 포함해 스타트랙 바깥에서는 소리가 나지 않습니다. `내 영상 끄기`는 나에게만 적용합니다.
- 재생 중 화면 일부가 보이면 내 영상도 계속 재생합니다. 화면이 완전히 벗어나거나 다른 창에 가려 플레이어를 표시할 수 없으면 내 영상만 멈춥니다. 자동 재생을 시작하거나 다시 시작하려면 화면의 절반을 넘게 보여야 하며, 화면이 작게 보일 때는 `내 영상 재생`을 직접 눌러 시작할 수 있습니다. 다른 탭으로 이동해도 내 재생을 멈춥니다. [유튜브 재생 정책](https://developers.google.com/youtube/terms/required-minimum-functionality)에는 자동 재생 시작 기준이 명시되어 있지만, 재생 중 화면이 극히 일부만 보이는 경우는 별도로 명시되어 있지 않습니다.
- 스타트랙에 사람이 한 명이라도 있으면 공유 재생은 유지합니다. 마지막 사람이 나간 뒤 5초가 지나면 공유 재생을 일시정지하고, 다시 들어오면 자동으로 재개합니다. 누군가 직접 일시정지한 영상은 자동으로 재개하지 않습니다.
- 브라우저에서 자동 재생을 막으면 `내 영상 재생`을 누릅니다. 외부 재생이 막힌 영상은 이용할 수 없습니다.
- 스타트랙의 `근처` 채팅은 객석과 무대 전체에 전달됩니다. 영상 상태는 서버가 다시 시작되면 초기화됩니다.

### LiveKit Cloud 연결

LiveKit Cloud 프로젝트의 URL, API Key, API Secret을 서버 환경 변수로 설정합니다. API Secret은 브라우저로 보내거나 저장소에 커밋하지 않습니다. 설정이 없으면 캠퍼스는 그대로 열리고 음성 연결만 사용할 수 없습니다.

로컬에서 설정할 때는 `.env.example`을 `.env.local`로 복사하여 값을 채우고 다음을 실행합니다.

```bash
set -a
source .env.local
set +a
npm run build
CAMPUS_BIND_HOST=127.0.0.1 PORT=18080 node app.js
```

이 단순 LiveKit 설정은 로컬 확인용입니다. 운영에서는 사용량을 예약하고 연결을 정리하는 관리 모드와 별도 환경 변수가 필요합니다. 실제 LiveKit Cloud URL은 `wss://`로 시작합니다.

### 이 컴퓨터에서만 시험하기

Docker가 있다면 LiveKit Cloud 계정 없이 두 개의 브라우저 탭으로 시험할 수 있습니다. 아래 개발용 키는 공개된 테스트 값이므로 운영 환경에서 사용하면 안 됩니다.

```bash
docker run --rm --name campus-livekit-test \
  -p 127.0.0.1:7880:7880 -p 127.0.0.1:7881:7881 -p 127.0.0.1:7882:7882/udp \
  livekit/livekit-server --dev --bind 0.0.0.0 --node-ip 127.0.0.1
```

다른 터미널에서 앱을 실행합니다.

```bash
npm install
npm run build
CAMPUS_BIND_HOST=127.0.0.1 PORT=18080 LIVEKIT_URL=ws://127.0.0.1:7880 LIVEKIT_API_KEY=devkey LIVEKIT_API_SECRET=secret node app.js
```

`http://127.0.0.1:18080/?nomock`을 두 탭에서 열고 각 탭의 음성 연결을 누릅니다(마이크도 함께 켜집니다). 한쪽에서 말하고 다른 쪽에서 듣습니다. 화면 공유는 두 캐릭터가 같은 회의실에 들어간 뒤 시험합니다. 이 주소는 이 컴퓨터에서만 열립니다. 이 명령에 `MEDIA_MEETINGS_TEST=local-only`를 추가하면 공개 및 비공개 회의 선택도 시험할 수 있습니다. 서버 주소가 `127.0.0.1`인 경우에만 켜집니다.

### 제공자와 사용량 시험

화면은 `src/media/types.ts`의 공통 기능을 사용합니다. 작은 시험 한도에 도달하면 LiveKit, Daily, Cloudflare 순서로 바뀝니다. 전환할 때 음성이 잠시 끊기고, 공유 중인 화면은 다시 선택해야 할 수 있습니다.

운영 관리 모드에서도 LiveKit → Daily → Cloudflare 순서로 전환합니다. 예약 한도에 닿거나 제공자를 사용할 수 없으면 기존 연결의 정리를 확인한 뒤 다음 제공자로 넘어갑니다. 세 제공자를 모두 사용할 수 없으면 음성과 화면 공유를 중단합니다. Daily와 Cloudflare는 무료량 초과 시 과금될 수 있고, 서버의 예상 사용량만으로 초과 청구를 완전히 막을 수 없습니다. 운영 조건과 남은 문제는 [미디어 운영 준비](docs/media-operations.md)를 확인합니다.

- 사용 전에 최대 연결 시간이나 예상 전송량을 예약하고, SQLite에 기록합니다. 기존 사용량을 포함한 예약을 35일 동안 보관합니다. 실제 사용이 더 짧아도 돌려주지 않아 서비스가 일찍 중단될 수 있습니다. 초기 계정 사용량이 빠지거나 다른 앱이 같은 계정을 사용하면 예약만으로 실제 한도를 알 수 없습니다.
- 서버를 다시 켜면 이전 연결을 먼저 정리합니다. 정리가 확인되지 않은 연결이 있으면 다음 서비스를 열지 않습니다. 여러 서버가 같은 SQLite 파일을 공유하는 구성은 지원하지 않습니다.
- LiveKit은 연결 시간과 예상 수신 전송량을 함께 예약합니다. 방의 참가자 수를 제한하고 브라우저의 전송 속도도 줄입니다. 서버 예약량은 실제 사용량이 아니며, 변조된 클라이언트의 전송량까지 강제로 제한하지는 못합니다.
- Daily는 만료 시 퇴장하는 토큰을 사용하고, 서버가 현재 위치를 기준으로 수신 권한을 설정합니다. Daily에는 코드 밖의 계정 사용을 막는 지출 상한이 없습니다.
- Cloudflare SFU는 최근 31일과 오늘의 계정 분석 사용량을 읽고 예상 전송량과 더해 보수적으로 제한합니다. 조회 가능한 기간이 부족하거나 사용량을 읽지 못하면 연결을 막습니다. EC2가 꺼져도 별도 Worker가 만료된 세션을 정리하도록 시험했습니다. 분석은 청구서와 다를 수 있고, Worker나 SFU의 장애와 처리 지연까지 막을 수는 없습니다.
- Daily와 Cloudflare에는 등록된 결제수단으로 청구될 수 있습니다. 예상값과 여유분은 청구가 0원임을 보장하지 않습니다.
- 비공개 회의는 비밀번호를 확인합니다. 사용자 인증과 초대 관리가 없어 민감한 내용을 다루는 용도로 사용할 수 없습니다.

Daily와 Cloudflare의 기록을 서버에서 따로 살펴볼 수 있습니다. 비밀값은 저장소에 올리지 않은 로컬 환경 변수 파일에 보관합니다.

```bash
set -a
source .env.daily-cloud.local
source .env.cloudflare-analytics.local
set +a
DAILY_BUDGET_FILE="$PWD/.env.daily-budget.local" node scripts/daily-usage.mjs
node scripts/cloudflare-usage.mjs
```

Daily 회의 기록에는 집계 지연이나 조회 기간 경계로 인한 누락이 있을 수 있습니다. 위의 Daily 파일은 예전 로컬 시험 기록이며 운영 저장소가 아닙니다. Cloudflare 분석 데이터 역시 청구서가 아닙니다. 어느 한쪽 조회에 실패하면 0으로 간주하지 않습니다.

## 하루들 로그인 연동

설정 창의 **[하루들 연동하기]**를 누르면 하루들에서 확인을 받고 돌아와, 하루들 닉네임으로 캠퍼스에 들어온다. 하루들이 발급한 60초짜리 서명 토큰을 캠퍼스가 직접 확인하고, 회원 ID · 닉네임 · 프로필 사진만 받는다. 하루들 DB와 기존 코드는 바꾸지 않는다. 설정이 없으면 버튼이 숨고 모두 게스트로 동작한다. 자세한 흐름과 설정은 [docs/harudle-login.md](docs/harudle-login.md).

## 시간과 날씨

- 시간은 서버 시각과 판교 위치를 기준으로 흐릅니다. 해의 위치와 높이에 따라 하늘, 석양, 주변 건물이 천천히 바뀝니다. 캠퍼스 안은 조명을 켠 상태로 유지해 밤에도 밝습니다. 흐린 날에는 해와 석양이 옅게 보입니다. 날씨 제공 서비스가 응답하지 않아도 시간은 계속 흐릅니다.
- 해의 위치는 SunCalc로 계산합니다. SunCalc의 사용 조건은 [`static/licenses/suncalc.txt`](static/licenses/suncalc.txt)에 있습니다.
- Open-Meteo의 판교 근처 **예보 모델**을 사용합니다. 관측값이 아니므로 실제 날씨와 다르거나 늦을 수 있습니다. 서버에서 15분 동안 응답을 보관하고, 실패하면 마지막 정보를 최대 2시간 동안 사용합니다. 날씨는 안내 상자 없이 하늘과 창밖에 반영합니다.
- 기본 Open-Meteo API는 비상업적 이용과 평가용입니다. 상업적 운영에는 사용 조건을 확인하고 구독이 필요하면 `OPEN_METEO_API_KEY` 환경 변수에 키를 넣습니다. 키가 있으면 서버가 고객용 주소로 요청하며, 키는 브라우저에 전달하지 않습니다. 데이터 출처는 화면에 표시합니다.

## 배포 (무중단)

AWS 서울 리전 EC2 (t4g.small, Amazon Linux 2023, Project=harudle).
주소는 https://campus.harudle.com 이고, Caddy가 인증서를 자동으로 받습니다. 앱은 3000번, Caddy가 80·443을 받습니다.

`main`에 푸시하면 끝입니다. 서버의 감독 프로세스가 20초 안에 알아채고 아래 순서로 바꿉니다.

1. **검사**: 새 커밋을 임시 폴더에 풀어 `scripts/check.mjs`를 돌립니다. 실패하면 배포하지 않습니다.
2. **새 워커**: 같은 포트에 새 버전 워커를 띄우고, 피드를 미리 받아 둔 뒤 "준비됐어요"를 받을 때까지 기다립니다.
3. **옛 워커 비우기**: 새 연결을 끊고, 처리 중인 요청을 마친 뒤 내려갑니다. 접속 중인 크루는 WebSocket이 끊기자마자 새 워커로 다시 붙습니다 (0.2초 안팎).
4. **되돌리기**: 새 워커가 30초 안에 준비되지 않거나 죽으면, 옛 워커를 그대로 두고 작업 폴더를 이전 커밋으로 돌립니다. 그 커밋은 다시 시도하지 않습니다.

페이지를 열어 둔 사람에게는 "새 버전이 나왔어요 · 새로고침" 버튼이 뜹니다. 강제로 새로고침하지는 않습니다.

- 지금 어떤 버전이 돌고 있는지: `curl https://campus.harudle.com/healthz` → `ok <커밋>`
- 되돌리고 싶으면: `git revert` 후 푸시하면 같은 방식으로 무중단 반영됩니다.
- `server.js`(감독) 자체를 바꾼 커밋은 워커만 먼저 바뀌고, 감독은 다음 재시작 때 반영됩니다.
- 끄려면 서비스 환경 변수에 `AUTO_DEPLOY=0`.

### 검증한 것

로컬에서 가짜 원격 저장소로 세 가지 커밋을 차례로 밀어 넣는 동안, `/healthz`를 50ms마다 1,316번 두드려 실패 0번이었습니다.

| 커밋 | 결과 |
| --- | --- |
| 정상 변경 | 무중단 교체, WebSocket은 0.2초 만에 새 워커로 재접속 |
| 실행하자마자 죽는 코드 | 새 워커만 죽고 옛 워커 유지, 작업 폴더 되돌림 |
| 엘리베이터 홀이 막히는 배치 | 검사에서 걸러져 배포 안 됨 |

층 배치를 바꾸려면 `src/engine/world.ts`의 `makeFloor()`만 고치면 됩니다. (`public/`은 예전 서버용 단일 HTML 버전이 남아 있는 자리이고, 사이트 정적 파일은 `static/`에 둡니다.)
